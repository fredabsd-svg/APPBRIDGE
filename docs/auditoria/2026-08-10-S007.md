## Decisões tomadas

### D-01: Padrão de Token JWT (HS256)
- **Decisão:** Usar HS256 (HMAC com chave simétrica) para assinatura de token
- **Rationale:** Alinhado com ADR-0001 (autenticação base). Chave armazenada em dotnet user-secrets (desenvolvimento) e Key Vault (produção). Suficiente para MVP-0.
- **Alternativas rejeitadas:** RS256 (requer par assimétrico, mais complexo); ES256 (requer curva elíptica, não necessário)

### D-02: Claims de JWT
- **Decisão:** Incluir `sub` (userId), `unique_name` (userIdentifier), `tenant_id`, `iat` (issued at)
- **Rationale:** `sub` é padrão JWT para subject; `tenant_id` é essencial para multi-tenancy; `iat` é útil para auditoria
- **Não incluído:** `role` (será adicionado em T-02.5 com autorização por aplicativo); `app_id` (não aplicável em autenticação)

### D-03: Password Verification Placeholder
- **Decisão:** AuthenticationService.AuthenticateAsync() não valida senha no MVP-0
- **Rationale:** Password hashing é T-02.6 (fora do escopo de T-02.3). Placeholder permite testes e integração sem exigir criptografia completa.
- **Risco:** CRÍTICO se desplegado em produção sem T-02.6. Mitigação: comentário TODO + logging de warning.

### D-04: Estrutura de Folder para Serviços de Autenticação
- **Decisão:** JwtTokenService e AuthenticationService vivem em `Infrastructure/Services/Authentication/`
- **Rationale:** São implementações de detalhes (JWT é biblioteca específica), não abstrações de negócio. Mudança futura para Azure AD/Entra pode resultar em nova pasta `Infrastructure/Services/AzureAdAuthentication/`.

### D-05: Middleware de Autenticação vs. Atributo [Authorize]
- **Decisão:** Usar middleware `app.UseAuthentication()` + atributo `[Authorize]` nos controllers
- **Rationale:** Padrão ASP.NET Core, separação clara de preocupações. Tenant context isolation fará parte de T-02.6 (middleware customizado).

## Riscos identificados

### Risco R-026 (novo): Password Verification Ausente
- **Severidade:** CRÍTICA
- **Descrição:** AuthenticationService aceita qualquer string como senha no MVP-0
- **Impacto:** Qualquer pessoa que conheça um `userIdentifier` pode autenticar-se
- **Mitigação:** TODO comment no código + aviso em AUTHENTICATION-TESTING.md + T-02.6 bloqueada até implementação
- **Resolução:** T-02.6 implementa bcrypt ou ASP.NET Identity PasswordHasher

### Risco R-027 (novo): Tenant Context Não Isolada em Request
- **Severidade:** ALTA
- **Descrição:** Endpoint protegido retorna dados baseado em JWT claim `tenant_id`, mas não há middleware validando que o recurso acessado pertence àquele tenant
- **Impacto:** Vulnerabilidade de cross-tenant traversal se recurso não validar tenant
- **Mitigação:** Design de T-02.5 e T-02.6 inclui validação obrigatória por recurso
- **Resolução:** T-02.6 implementa middleware de contexto de tenant + testes de negativa
