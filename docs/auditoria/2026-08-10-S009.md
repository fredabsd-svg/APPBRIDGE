## Decisões tomadas

### D-10: BCrypt WorkFactor
- **Decisão:** workFactor = 12 (padrão atual de segurança)
- **Rationale:** ~100ms por hash, aceitável para MVP-0 com 10 usuários simultâneos
- **Alternativas:** workFactor 10 (50ms, menos seguro), workFactor 14 (200ms, overkill para MVP)
- **Futuro:** Considerar ajuste se dogfood revelar latência inaceitável

### D-11: TenantContextService Simplista
- **Decisão:** Implementação em memória (scoped), sem persistência
- **Rationale:** Contexto precisa existir apenas durante a request atual. DI container gerencia lifetime.
- **Alternativas:** Armazenar em HttpContext.Items (mais .NET idiomático, mas menos testável)
- **Vantagem:** Testável sem mock de HttpContext

### D-12: Middleware Order para Exception Handling
- **Decisão:** UseExceptionHandling() no **início** da pipeline (logo após builder.Build())
- **Rationale:** Precisa cercar todos outros middlewares para capturar exceções geradas por eles
- **Placement atual:** antes de UseSwagger, UseHttpsRedirection, etc.
- **Alternativa rejeitada:** No meio (perderia exceções de middlewares posteriores)

### D-13: Exception Mapping Simplista
- **Decisão:** Switch case em GetErrorDetails(), não classe separada
- **Rationale:** Sete cases apenas, sem lógica complexa. Legibilidade > abstração prematura.
- **Futuro:** Se crescer > 10 cases, considerar factory ou dictionary

### D-14: ValidationErrors Array (não dict)
- **Decisão:** Dictionary<string, string[]> (campo → lista de mensagens)
- **Rationale:** Padrão ASP.NET Core ModelState. Um campo pode ter múltiplas mensagens.
- **Alternativas:** Dictionary<string, string> (simples, mas perde múltiplos erros por campo)
