# Entity Framework Core Migrations — AppBridge

**Status:** Foundation ready for initial migration (T-02.1)  
**Tool:** EF Core 8.0 with PostgreSQL provider  
**Convention:** UUID v7, timestamptz UTC, soft-delete via `deleted_at`

---

## 1. Quick Start

### Create Initial Migration

```bash
cd src/AppBridge.ControlPlane.Infrastructure

# Create migration (requires .NET CLI)
dotnet ef migrations add Initial \
  --project . \
  --startup-project ../Api \
  --context AppBridgeDbContext

# Or: from repo root
dotnet ef migrations add Initial \
  --project src/AppBridge.ControlPlane/Infrastructure \
  --startup-project src/AppBridge.ControlPlane/Api
```

### Apply Migration to Database

```bash
cd src/AppBridge.ControlPlane.Api

# Update database to latest migration
dotnet ef database update \
  --project ../Infrastructure \
  --context AppBridgeDbContext

# Or: from repo root
dotnet ef database update \
  --project src/AppBridge.ControlPlane/Infrastructure \
  --startup-project src/AppBridge.ControlPlane/Api
```

### View Pending Migrations

```bash
dotnet ef migrations list \
  --project src/AppBridge.ControlPlane/Infrastructure \
  --startup-project src/AppBridge.ControlPlane/Api
```

## 2. Migration Architecture

### Folder Structure

```
src/AppBridge.ControlPlane/Infrastructure/
├── Migrations/
│   ├── 20260809000000_Initial.cs          (generated by EF)
│   ├── 20260809000000_Initial.Designer.cs (generated by EF)
│   └── AppBridgeDbContextModelSnapshot.cs (generated by EF)
├── Persistence/
│   └── AppBridgeDbContext.cs
└── Persistence.csproj
```

### Generated Files

EF Core generates three files per migration:

1. **Migration class** (`20260809000000_Initial.cs`):
   - Contains `Up()` method (apply migration)
   - Contains `Down()` method (rollback)
   - Generated from model changes

2. **Designer metadata** (`20260809000000_Initial.Designer.cs`):
   - Snapshot of model state at migration time
   - Used by EF to detect incremental changes

3. **Model snapshot** (`AppBridgeDbContextModelSnapshot.cs`):
   - Current model state
   - Updated with each new migration

### Key Principles

- **Never edit generated migration files** — regenerate if needed
- **Review generated SQL** — ensure it matches intent
- **Migrations are immutable** — once pushed, never modify
- **Rollback via new migration** — create Down() as separate migration if needed
- **Test on dev database first** — migrations are destructive

## 3. Workflow: From Code Change to Production

### Step 1: Update Entity Model

Edit `Core/Entities/*.cs`:

```csharp
// Add a new property to User entity
public class User
{
    // ... existing properties ...

    /// <summary>
    /// New field to track user's preferred language.
    /// </summary>
    public string PreferredLanguage { get; set; } = "pt-BR";
}
```

### Step 2: Update DbContext (if needed)

Edit `Infrastructure/Persistence/AppBridgeDbContext.cs`:

```csharp
modelBuilder.Entity<User>(entity =>
{
    // ... existing config ...

    // Add column configuration
    entity.Property(e => e.PreferredLanguage)
        .HasMaxLength(10)
        .HasDefaultValue("pt-BR");
});
```

### Step 3: Create Migration

```bash
cd src/AppBridge.ControlPlane.Infrastructure

dotnet ef migrations add AddPreferredLanguageToUser \
  --startup-project ../Api

# Generates:
# - 20260809120000_AddPreferredLanguageToUser.cs
# - 20260809120000_AddPreferredLanguageToUser.Designer.cs
```

### Step 4: Review Generated Migration

Open `Migrations/20260809120000_AddPreferredLanguageToUser.cs`:

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.AddColumn<string>(
        name: "PreferredLanguage",
        table: "users",
        type: "character varying(10)",
        maxLength: 10,
        nullable: false,
        defaultValue: "pt-BR");
}

protected override void Down(MigrationBuilder migrationBuilder)
{
    migrationBuilder.DropColumn(
        name: "PreferredLanguage",
        table: "users");
}
```

**Review Checklist:**
- [ ] SQL syntax is correct
- [ ] Column type matches intent (varchar, int, uuid, timestamptz, jsonb)
- [ ] Constraints are appropriate (NOT NULL, UNIQUE, DEFAULT)
- [ ] Foreign key relationships are correct
- [ ] Index creation for performance
- [ ] No accidental column drops

### Step 5: Test on Development Database

```bash
# Ensure dev database is running (Docker or local PostgreSQL)
docker ps | grep postgres

# Update database
dotnet ef database update \
  --startup-project ../Api

# Verify: connect to database
psql -U postgres -d appbridge_dev -c "\d users"

# Should show new column: preferred_language
```

### Step 6: Commit Migration

```bash
git add src/AppBridge.ControlPlane/Infrastructure/Migrations/
git commit -m "feat: add PreferredLanguage column to users table

- Supports language selection in launcher (RFC-041)
- Defaults to pt-BR for Brazilian Portuguese
- Nullable: false (required field)

Refs: RFC-041"
```

### Step 7: CI/CD Validation

When PR is opened:
- [ ] GitHub Actions runs `dotnet ef migrations list`
- [ ] Verifies migrations compile
- [ ] Does NOT apply to CI database (unsafe)
- [ ] Reports migration summary in PR comment

### Step 8: Production Deployment

During deployment:
```bash
# Usually in deployment script
dotnet ef database update --environment Production
```

Or via Infrastructure-as-Code (Terraform/CloudFormation):
```hcl
# Example: Azure SQL Database migrations
resource "azurerm_mssql_database_migration_service" "db_migration" {
  # ... parameters ...
  migration_commands = [
    "dotnet ef database update --environment Production"
  ]
}
```

## 4. Common Scenarios

### Scenario 1: Add a New Column

```bash
# Edit entity, then:
dotnet ef migrations add AddColumnNameToTableName

# Generates:
migrationBuilder.AddColumn<string>(
    name: "column_name",
    table: "table_name",
    type: "character varying(100)",
    nullable: false,
    defaultValue: "");
```

### Scenario 2: Rename a Column

```csharp
// Entity change
public class User {
    public string PhoneNumber { get; set; }  // was: Phone
}

// Migration (may need manual adjustment)
migrationBuilder.RenameColumn(
    name: "Phone",
    table: "users",
    newName: "PhoneNumber");
```

### Scenario 3: Add Index for Performance

```csharp
// In DbContext OnModelCreating
entity.HasIndex(e => new { e.TenantId, e.CreatedAt })
    .IsDescending(false, true);  // descending by date

// Migration:
migrationBuilder.CreateIndex(
    name: "IX_users_TenantId_CreatedAt",
    table: "users",
    columns: new[] { "TenantId", "CreatedAt" },
    descending: new[] { false, true });
```

### Scenario 4: Add Audit Trigger (Future)

When implementing ADR-0015 (PS-03, cryptographic chaining):

```csharp
// In OnModelCreating, after entity config
migrationBuilder.Sql(@"
    CREATE OR REPLACE FUNCTION audit_log_chain_hash()
    RETURNS TRIGGER AS $$
    BEGIN
        -- Calculate chain hash for this audit log entry
        NEW.chain_hash := encode(
            digest(
                (SELECT chain_hash FROM audit_logs
                 WHERE tenant_id = NEW.tenant_id
                 ORDER BY occurred_at DESC LIMIT 1) || 
                NEW.occurred_at::text || 
                NEW.action::text,
                'sha256'
            ),
            'hex'
        );
        RETURN NEW;
    END;
    $$ LANGUAGE plpgsql;

    CREATE TRIGGER audit_log_chain_hash_trigger
    BEFORE INSERT ON audit_logs
    FOR EACH ROW
    EXECUTE FUNCTION audit_log_chain_hash();
");
```

### Scenario 5: Rollback (Undo Last Migration)

```bash
# WARNING: Destructive operation
dotnet ef database update <PreviousMigrationName>

# Example: rollback from "AddPreferredLanguageToUser" to "Initial"
dotnet ef database update Initial

# Then remove migration files:
rm src/.../Migrations/20260809120000_AddPreferredLanguageToUser*
```

**Never do this in production** — instead, create a new migration that undoes the change.

## 5. Multi-Tenant Considerations

### Migration Behavior with Global Query Filters

When `AppBridgeDbContext` has a TenantId set (production):

```csharp
var context = new AppBridgeDbContext(options, tenantId: "00000000-0000-0000-0000-000000000001");
```

All queries are filtered by TenantId, **but migrations ignore filters**:

```csharp
// Migration always sees ALL tenants' data
public override void Up(MigrationBuilder migrationBuilder)
{
    // This runs against all rows, no tenant filtering
    migrationBuilder.Sql("UPDATE users SET is_active = true;");
}
```

**Implication:** If migration needs tenant-specific logic, implement in application code, not in migration.

### Example: Seed Data (Tenant-Aware)

```bash
# Create seed data migration
dotnet ef migrations add SeedInitialData

# In migration:
migrationBuilder.InsertData(
    table: "tenants",
    columns: new[] { "id", "identifier", "name", "is_active" },
    values: new object[] { Guid.NewGuid(), "dogfood", "Frederico Dogfood", true }
);
```

## 6. Database First vs Model First

**AppBridge uses Model First** (Code First):

1. ✅ Define entities in `Core/Entities/*.cs`
2. ✅ Update `AppBridgeDbContext.OnModelCreating()`
3. ✅ Generate migrations with `dotnet ef migrations add`
4. ✅ Apply with `dotnet ef database update`

**Not used:** Database First (reverse-engineer from existing schema).

## 8. Troubleshooting

### "Unable to resolve service for type 'AppBridgeDbContext'"

**Problem:** EF migrations can't find DbContext configuration.

**Solution:** Ensure `AppBridgeDbContextFactory` is in Infrastructure project and implements `IDesignTimeDbContextFactory<AppBridgeDbContext>`.

```bash
# Verify
find src -name "*DbContextFactory*"
```

### "One or more validation errors were detected during model generation"

**Problem:** Entity configuration is invalid.

**Solution:** Review error message and fix `OnModelCreating()` — common issues:
- Composite FK without `HasPrincipalKey()`
- Missing column type configuration
- Circular navigation properties

### "The migration 'X' has already been applied to the database"

**Problem:** Migration was already applied; trying to apply again.

**Solution:**
```bash
# Check current state
dotnet ef migrations list

# If migration exists but should be skipped:
dotnet ef database update <PreviousMigration>
dotnet ef migrations remove  # If not yet pushed
```

### "Column does not exist" after database update

**Problem:** Migration applied but column not visible.

**Solution:** Verify migration ran:

```bash
psql -U postgres -d appbridge_dev -c "
  SELECT migration FROM __ef_migrations_history
  ORDER BY applied DESC LIMIT 5;
"
```

## 9. Performance Considerations

### Indexes

Create indexes for frequently-queried columns:

```csharp
// In OnModelCreating
entity.HasIndex(e => new { e.TenantId, e.CreatedAt })
    .IsDescending(false, true)  // Optimize ORDER BY DESC on date
    .HasDatabaseName("IX_users_TenantId_CreatedAt_desc");
```

### Partitioning (Future)

For very large tables (audit_logs can grow to millions of rows):

```sql
-- Partition audit_logs by month (PostgreSQL 12+)
CREATE TABLE audit_logs (
  id UUID,
  occurred_at TIMESTAMPTZ,
  -- ...
) PARTITION BY RANGE (DATE_TRUNC('month', occurred_at));
```

### Statistics

Keep table statistics fresh:

```bash
# During maintenance window
ANALYZE audit_logs;
VACUUM ANALYZE audit_logs;
```
